# banner_parser — парсер наружной рекламы из Яндекс.Панорам

Собирает баннеры (билборды, сити-форматы, рекламные стенды) из Яндекс.Панорам в
таблицу Excel: **фото панорамы + вырезанный баннер + телефоны + тема + гео**.

> ⚠️ **Правовое.** Массовая выгрузка панорам нарушает пользовательское соглашение
> Яндекса (риск блокировок IP и юридических претензий). Параметры `min_delay` и
> `proxies` в `config.yaml` снижают нагрузку, но не отменяют риск. Ответственность
> за использование — на стороне пользователя.

## Пайплайн

```
meta-API (panoid, граф улиц, адреса)
   → сшивка обзорной панорамы (низкий зум)
   → детекция баннеров (репроекция в плоские виды + YOLO)
   → кроп bbox в МАКСИМАЛЬНОМ зуме (докачиваем только нужные тайлы)
   → OCR (easyocr) → телефоны (regex)
   → классификация темы (keyword / CLIP)
   → дедупликация (по телефонам / гео+азимут)
   → SQLite → выгрузка в Excel со встроенными фото
```

Ключевая экономия трафика: панорама целиком **не** хранится — детекция идёт по
обзору в низком зуме, а в макс.зуме докачивается только регион найденного баннера.

## Установка

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt          # ядро (без GPU)
# по мере подключения этапов:
pip install ultralytics easyocr open-clip-torch torch   # детекция/OCR/классификация (GPU)
pip install osmnx                                         # seed-точки по дорогам
```

## Использование

```bash
# Одна точка (ручной регион баннера — режим демо/отладки):
python -m banner_parser demo --lon 37.748763 --lat 55.712394 --region 0.66 0.63 0.795 0.86

# Резюмируемый автономный обход Москвы (OWLv2 сам находит баннеры):
python -m banner_parser crawl --lon 37.7050 --lat 55.6480          # без лимита — крутить пока не исчерпается очередь
python -m banner_parser crawl --lon 37.7050 --lat 55.6480 --limit 200   # ограничить число панорам за запуск

# Длительный запуск — только через обёртку: она делает cd в каталог проекта,
# берёт python3, ставит YOLO_CONFIG_DIR, пишет лог с flush и держит блокировку.
scripts/run_crawl.sh --limit 500
tail -f logs/crawl_*.log          # смотреть прогресс
python3 -m banner_parser stats    # сколько баннеров найдено
# Остановить: Ctrl-C или kill -TERM <pid> — причина остановки попадёт в лог
# Продолжить: тот же запуск — состояние (посещённые+очередь) в БД, обход резюмируется

# Обход прямоугольной области по дорогам:
python -m banner_parser grid --bbox 37.70 55.71 37.76 55.74 --road --step 40

# Выгрузка в Excel (опц. фильтр по теме) и статистика:
python -m banner_parser export --category недвижимость
python -m banner_parser stats
```

## Запуск на shared-хостинге (Beget)

Хостинг **сносит всю пользовательскую сессию при выходе из SSH**. Проверено:
`nohup`, `setsid`, `screen` и `tmux` умирают через несколько секунд после
отключения — фоновый обход «на ночь» так не оставить. Вычислительно сервер
задачу тянет: одна панорама — ~30 с и ~2,5 ГБ RSS, лимитов по памяти и CPU нет.

Два рабочих варианта:

1. **Живая SSH-сессия** — `scripts/run_crawl.sh --limit 500`, терминал не закрывать.
2. **Планировщик в панели Beget** (crontab на хостинге нет) — команда:

   ```
   /home/s/<user>/<site>/inmaps/scripts/run_crawl.sh --limit 200
   ```

   Каждый запуск обрабатывает свою порцию и завершается сам; состояние обхода
   лежит в БД, поэтому следующий запуск продолжает с того же места. Блокировка
   в скрипте не даёт двум запускам пересечься, если предыдущий ещё не закончил.

### Как читать лог при падении

Лог пишется с flush на каждой строке, поэтому хвост переживает убийство процесса.
Первым делом ищите одну из строк:

| строка в логе | что произошло |
|---|---|
| `=== ЗАВЕРШЕНО` | отработал сам, в строке время и пик памяти |
| `=== СИГНАЛ` | остановлен извне (Ctrl-C, `kill`, обрыв SSH) |
| `=== ИСКЛЮЧЕНИЕ` | упал, трассировка следом |
| ничего из перечисленного | убит `SIGKILL` — OOM либо снос сессии хостингом |

В последнем случае смотрите последнюю строку `жив:` — она показывает этап и
занятую память на момент смерти. Строка `=== СТАРТ` в начале лога содержит
каталог, интерпретатор, версии пакетов и свободное место — то, чего не хватало,
когда обход падал с `No module named banner_parser`.

Зависший процесс можно опросить без отладчика: `kill -USR1 <pid>` выведет
в лог стеки всех потоков.

## Конфигурация — `config.yaml`

- `detector.backend`: `region` (ручные регионы, демо) или `yolo` (обученные веса).
- `panorama.overview_zoom` / `crop_zoom`: зум обзора для детекции и финального кропа.
- `ocr.enabled`, `classify.backend`, `http.min_delay`, `http.proxies` — см. комментарии в файле.

## Структура

```
banner_parser/
  yandex/     meta-API, сшивка панорамы, кроп в макс.зуме, обход графа
  detect/     репроекция equirect→перспектива, детектор (region | YOLO)
  ocr/        easyocr + извлечение телефонов
  classify/   тема баннера (keyword baseline / CLIP)
  storage/    SQLite + дедупликация
  export/     Excel со встроенными фото
  pipeline.py оркестрация одной панорамы
  cli.py      demo | crawl | grid | export | stats
```
