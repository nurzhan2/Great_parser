# Развёртывание с нуля

Инструкция проверена целиком: на чистом venv установлены зависимости и
выполнены все команды ниже. Где проверка была частичной, это сказано прямо.

## 1. Требования

- **Python 3.10–3.13.** На 3.14 не собирается `paddlepaddle` (колёс нет), но
  он опционален. Проверено на 3.10.12 (сервер) и 3.14 (локально, без paddle).
- ~4 ГБ на диске под зависимости и веса моделей, ~2,5–4,2 ГБ оперативной
  памяти на время детекции.
- Интернет к `api-maps.yandex.ru`, `pano.maps.yandex.net` и Hugging Face
  (однократно — за весами детектора).

## 2. Установка

```bash
git clone <репозиторий> inmaps && cd inmaps
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt   # ядро: requests, Pillow, numpy, PyYAML, XlsxWriter
pip install torch transformers easyocr   # детектор OWLv2 + OCR, ~2 ГБ
```

Опционально:

```bash
pip install osmnx        # для grid --road: посев точек по дорогам
pip install open-clip-torch   # для backend=clip в verify/classify
pip install anthropic    # только если будете включать VLM (см. раздел 6)
```

Веса детектора (~600 МБ) скачиваются автоматически при первом запуске.

## 3. Конфигурация

Всё в `config.yaml`, значения переопределяются переменными окружения
`BP_<СЕКЦИЯ>_<КЛЮЧ>` — например `BP_OCR_BACKEND=vlm`, `BP_STORAGE_DB_PATH=/tmp/test.sqlite`.

Что стоит проверить перед первым запуском:

| ключ | смысл |
|---|---|
| `crawl.bbox` | рамка обхода `[min_lon, min_lat, max_lon, max_lat]`. По умолчанию Москва |
| `crawl.min_distance_m` | 250 — минимальная дистанция между снимаемыми точками |
| `ocr.backend` | `easyocr` (бесплатно) / `paddle` / `vlm` (платно, точнее) |
| `detector.conf` | 0.22 — порог детекции. Менять не нужно, настоящие щиты идут 0.49–0.55 |
| `storage.db_path` | куда писать базу |

## 4. Первый обход

```bash
export YOLO_CONFIG_DIR=/tmp/Ultralytics     # иначе ultralytics полезет в ~/.config
python3 -m banner_parser demo --lon 37.6550 --lat 55.7000   # одна точка, ~40 с
python3 -m banner_parser crawl --lon 37.6550 --lat 55.7000 --limit 10 --log logs/crawl.log
python3 -m banner_parser stats
```

`crawl` резюмируемый: состояние (посещённые панорамы и очередь) лежит в БД,
повторный запуск продолжает с того же места. Остановка — `Ctrl-C` или
`kill -TERM`, причина попадёт в лог.

Для длительной работы — только через обёртку, она закрывает все известные
грабли (каталог, интерпретатор, переменные, блокировка, проверка места):

```bash
scripts/run_crawl.sh --limit 30
```

## 5. Выгрузка

```bash
python3 -m banner_parser export --out banners.xlsx --all       # всё
python3 -m banner_parser export --out realty.xlsx --realty     # только недвижимость
```

`--realty` кладёт частные объявления на отдельный лист: это физлица,
а не рекламодатели рынка.

## 6. Включение VLM

Без VLM работают детекция, адрес, координаты, фото и базовый OCR (31%
распознанных слов). VLM добавляет то, чего иначе нет вовсе: рекламодателя,
тип конструкции, тему, флаг недвижимости и застройщика.

1. Ключ берётся на `console.anthropic.com`, пополняется там же.
2. Кладётся **только в переменную окружения**, в конфиг и git не попадает:
   ```bash
   export ANTHROPIC_API_KEY=sk-ant-...
   ```
   Для автономной работы — в `~/.bashrc` на сервере.
3. Включается одной строкой в `config.yaml`:
   ```yaml
   ocr:
     backend: vlm
   ```

Что меняется, по замерам:

| | EasyOCR | VLM |
|---|---|---|
| распознано слов | 31,2% | **94,3%** |
| рекламодатель | нет | 17 из 19 кропов с брендом |
| тип конструкции | нет | 79% записей |
| стоимость | 0 | **$0,0029 за кроп** |

При ~2,2 кропа на точку: **~$7 на 1000 точек**, **~$70 на 10 000**.

Результаты кэшируются по хэшу кропа — повторный прогон тех же картинок
бесплатен. Если баланс кончится, обход не упадёт: движок откатится на
EasyOCR, а в поле `ocr_engine` будет видно, какие записи стоит переспросить
у VLM после пополнения.

## 7. Автономная работа на Beget

Хостинг **убивает все процессы при выходе из SSH** — проверено: `nohup`,
`setsid`, `screen` и `tmux` умирают одинаково. Поэтому длительный обход
запускается либо при живой сессии, либо из планировщика в панели.

Строка для планировщика, раз в час:

```
/home/s/<логин>/<сайт>/inmaps/scripts/run_crawl.sh --limit 40
```

Расчёт: ~40 с на точку плюс ~25 с на старт, то есть 40 точек ≈ 30 минут —
вдвое меньше интервала. Обёртка держит блокировку, поэтому если предыдущий
запуск затянулся, следующий отобьётся и напишет об этом в лог.

## 8. Если что-то пошло не так

Лог пишется с flush на каждой строке, поэтому хвост переживает даже
убийство процесса. Ищите одну из строк:

| строка | что произошло |
|---|---|
| `=== ЗАВЕРШЕНО` | отработал сам |
| `=== СИГНАЛ` | остановлен извне (Ctrl-C, kill, обрыв SSH) |
| `=== ИСКЛЮЧЕНИЕ` | упал, трассировка следом |
| ничего из этого | убит SIGKILL: OOM или снос сессии хостингом |

Строка `=== СТАРТ` в начале лога содержит каталог, интерпретатор, версии
пакетов и свободное место — этого хватает, чтобы отличить «запустили не из
той папки» от «кончилась память».

Зависший процесс можно опросить без отладчика: `kill -USR1 <pid>` выведет
в лог стеки всех потоков.
